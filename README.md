# crcut — авто-монтажёр TikTok по Clash Royale

Кидаешь записи матчей в `inbox/` → одна команда → три готовых вертикальных ролика
с музыкой, озвучкой, SFX, сабами, зумами и переходами. Заливать можно сразу.

## Установка

Нужны **ffmpeg** (с `ffprobe`) и **uv**. Python 3.12 uv поставит сам.

```bash
brew install ffmpeg uv                  # macOS; Linux: apt install ffmpeg + astral.sh/uv

git clone git@github.com:maksym-simonchuk/aftograf-tiktok-clash-royale.git
cd aftograf-tiktok-clash-royale
uv sync --extra beats                   # без --extra beats биты своей музыки не детектятся
```

Проверить, что всё встало:

```bash
uv run pytest -q                        # 32 теста на синтетической фикстуре
```

## Как пользоваться

**1. Кидаешь записи матчей в `inbox/`** — как есть, с телефона. Формат вертикальный
(9:16), любой размер: приводится к 1080×1920, узкое дополняется размытым фоном.
Звук исходника не нужен — детект чисто по картинке.

```
inbox/
  МАТЧ1.MP4
  МАТЧ2.MP4
  МАТЧ3.MP4
```

**2. Одна команда:**

```bash
uv run crcut inbox
```

```
analyzing 3 file(s)...
  МАТЧ1.MP4: 6 highlight(s), match 7.9-85.5s
  ...
music: bed_140bpm.wav (126 beats)
voice: Milena (grandpa)
rendering montage_v1 -> out/montage_v1_20260813-141805.mp4  (42.4s)
rendering montage_v2 -> out/montage_v2_20260813-141805.mp4  (27.4s)
rendering montage_v3 -> out/montage_v3_20260813-141805.mp4  (53.9s)
done -> out
```

**3. Забираешь из `out/`** три `.mp4` и три `.txt` с заголовком и хэштегами —
скопировать в описание поста. Первый прогон на трёх матчах ≈ 3 минуты, повторные
быстрее: анализ кэшируется в `.crcut/` (сбросить — `--no-cache`).

С `--clips` вместо монтажа — короткие нарезки: клип ≤20 секунд на каждый
хайлайт, хронологически, со своим треком, заголовком и `.txt` рядом. Раскладка —
папка на матч (`out/clips/МАТЧ1/МАТЧ1_01.mp4` …), чтобы заливать в TikTok
пачками и не путать, откуда клип.

## Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--variants N` | `3` | сколько вариантов монтажа рендерить |
| `--duration С` | `42` | целевая длина основного варианта |
| `--clips` | — | вместо монтажа — клип ≤20с на каждый хайлайт, папка на матч в `out/clips/` |
| `--lang ru\|en` | `ru` | язык заголовков и сабов |
| `--music ФАЙЛ` | — | один трек на все варианты вместо ротации по `assets/music/` |
| `--no-music` | — | немой рендер: звук цепляешь в приложении TikTok |
| `--voice ИМЯ` | дед | системный голос, который читает сабы |
| `--voice-style С` | `grandpa` | как этот голос обработать: `grandpa` / `grandpa_deep` / `hype` / `rasp` / `clean` |
| `--no-voice` | — | без озвучки |
| `--voices` | — | показать установленные голоса и выйти |
| `--out ПАПКА` | `out` | куда складывать |
| `--analyze-only` | — | только `out/plan.json`, без рендера |
| `--from-plan Ф` | — | рендер по готовому (можно правленому руками) плану |
| `--debug` | — | `out/debug/`: сигналы в CSV и фильтрграфы ffmpeg |
| `--no-cache` | — | переанализировать, игнорируя `.crcut/` |

Примеры:

```bash
uv run crcut inbox --variants 1                    # только основной ролик
uv run crcut inbox --lang en --duration 55         # английский, подлиннее
uv run crcut inbox --clips                         # нарезки ≤20с, папка на матч
uv run crcut inbox --no-music                      # звук добавлю сам в TikTok
uv run crcut --voices                              # какие голоса есть в системе
uv run crcut inbox --voice Milena                  # читать конкретным голосом
uv run crcut inbox --voice-style clean             # без состаривания, чистый голос
uv run crcut inbox --analyze-only --debug          # посмотреть, что нашёл детект
uv run crcut --from-plan out/plan.json             # перерендер по правленому плану
```

## Как находит моменты

Без датасета и без хардкода координат. **Счётчика корон в HUD у Clash Royale
нет** — во время матча видны только две руки карт и таймер, поэтому моменты
читаются с самой картинки: движение в арене, яркие вспышки и **тряска камеры**
(игра трясёт экран на каждом тяжёлом ударе). Три сигнала складываются в
робастных z-оценках → `hype`, пики `hype` = хайлайты, ×1.5 за клатч в последние
30с.

Обратная сторона того же факта даёт гейт «матч идёт»: HUD пиксельно стабилен всю
игру и полностью другой на экранах загрузки и победы. Кадры, чьи HUD-строки
совпадают с медианой матча, — ровно игровые; интро и финалка в монтаж не попадают
без всякого детекта склеек.

## Что в папке на выходе

Одна команда — три готовых ролика, между которыми есть из чего выбрать: у каждого
свой холодный старт, своя длина и свой заголовок.

| Файл | Длина от `--duration` | Зачем |
|---|---|---|
| `montage_v1_<дата>.mp4` | ×1.0 (~42с) | основной |
| `montage_v2_<дата>.mp4` | ×0.62 (~26с) | короткий, на залипание в петле |
| `montage_v3_<дата>.mp4` | ×1.28 (~54с) | длинный, на время досмотра |

Рядом с каждым — `.txt` с заголовком и хэштегами. `--variants N` меняет их число.

## Музыка

Трендовые звуки лицензированы и качаются только в самом TikTok — и цеплять их
надо там же, потому что алгоритмический буст за трендовый звук живёт в приложении.
Поэтому crcut ничего не качает сам, а играет то, что лежит:

- в `assets/music/` лежат треки → **свой трек на каждый вариант**, и каждый вариант
  снапится на сетку **своего** трека (`detect_beats` через `librosa`), а не соседнего;
- какие именно три из пятнадцати — зависит от содержимого `inbox/`: смещение по пулу
  берётся хэшем имён исходников, так что другой набор матчей → другая музыка, а тот
  же набор звучит одинаково при повторном прогоне;
- папка пуста → синтезируются чиптюн-беды (`src/crcut/music.py`), **разные на
  каждый вариант**, чтобы три ролика подряд не звучали как один:

| Бед | Гармония | Барабаны | Настроение |
|---|---|---|---|
| `drive` | A2 F2 C3 G2, квинты | бочка на каждую долю | безопасный, тянет что угодно |
| `dark` | E2 A2 D2 G2, минорная септима | бочка со смещением | тяжелее, мрачнее |
| `rush` | B2 D3 A2 C3, широкое голосоведение | частый хлопок | яркий, паникующий |

BPM у синтезированных бедов один — 140. Это не лень: их сетка точная по построению,
без `librosa` и без детекта, а разнообразие набирается гармонией и барабанами, а не
темпом. Проверено на футаже: все 18 / 12 / 23 склейки лежат в пределах 1 мс от доли.

**140 BPM выбран не наугад** — это ровно центр фонка (110–160, типовые 140) и
верх бразильского фанка-монтажем (120–150). То есть если потом положишь в
`assets/music/` настоящий фонк-трек, он ляжет на ту же сетку без перенастройки.
Что реально крутится под Clash Royale в TikTok сейчас: `FUNK BASICO`,
`MONTAGEM REVOLUCAO MUSICAL (super slowed)`, `Holy War Hospital`, хардстайл-ремиксы
(`Levi Heron — The Glen`, 145–165 BPM — этот темп в сетку уже не попадёт).
Легально скачать похожее: [Pixabay](https://pixabay.com/music/search/tiktok%20phonk%20edit/),
[Tunetank](https://tunetank.com/discover/genres/phonk/) — кладёшь mp3 в
`assets/music/`, и синтез больше не используется.

### Что уже лежит в `assets/music/`

**15 треков**, скачаны с [ccMixter](https://ccmixter.org) через их публичный API с
фильтром `lic=open` — это лицензии Creative Commons **Attribution**: коммерческое
использование и ремикс разрешены **при указании автора**. Автора надо ставить в
описание ролика; таблица «файл → трек → автор → лицензия → ссылка» лежит рядом, в
`assets/music/ATTRIBUTION.md`.

Отбор объективный, не на слух. Скачано 285 песен (жанровые теги, 90–360 с, не больше
трёх на автора), дальше два прохода `librosa`:

1. **плотность и тон** — `steady` (10-й / 90-й перцентиль RMS: низкий = «рыхлый»),
   `spectral_flatness` (шум против тона), `spectral_centroid` (не глухо и не резко),
   крест-фактор и **чёткость доли** — автокорреляция огибающей атак на периоде такта,
   потому что именно по доле и режется монтаж;
2. **энергия** по верхушке первого прохода — низ 50–160 Гц, частота атак и громкость
   мастера. Без него побеждали спокойные вещи: они плотные и тональные, но под
   Clash Royale не годятся.

Итог: 15 штук, ≤1 трек на автора и ≤3 на жанр, 89–136 BPM. Первый пул (20 треков)
заменён целиком — он собирался фильтром «инструментал», а тот отдавал лупы и стемы
вместо песен, и три реально звучавших трека оказались самыми рыхлыми в пуле.

Каждый кандидат перед укладкой открывается через `librosa.load`: один mp3 ffmpeg
читал, а libsndfile — нет, и он уронил бы прогон на `detect_beats`.

Сама папка в git не лежит (`.gitignore`), так что после клона её надо наполнить
самому — либо своими файлами, либо теми же ccMixter-ссылками из `ATTRIBUTION.md`.

## Звуковые эффекты

Ничего не синтезируется. Играет только то, что лежит в `assets/sfx/`
(`.wav/.mp3/.m4a/.aac/.ogg`, крутятся по кругу, по одному на момент). Папка пустая
— значит звукового слоя нет вообще, удар несут зум и переход.

Так вышло потому, что моменты и есть места склейки: синтезированный удар попадал
ровно на каждую смену кадра, и это читалось не как акцент, а как щелчок. Убран
целиком, а не переставлен по времени.

## Сведение

Одна цепочка на весь ролик, всё приводится к 48 кГц / stereo / float на входе
(`sidechaincompress` не берёт входы с разным форматом):

| Шаг | Зачем |
|---|---|
| `sidechaincompress` музыки по шине голоса | музыка приседает **только пока дед говорит**, а не −5 dB на весь ролик |
| `amix=duration=longest:normalize=0` | без автонормировки, иначе уровень пляшет от числа слоёв |
| `alimiter=limit=0.95` | потолок перед замером |
| `loudnorm=I=-14:TP=-1.5:LRA=11` | один уровень у всех вариантов: 28-секундный и 55-секундный ролик звучат одинаково громко |
| `aresample=48000:filter_size=64` | `loudnorm` отдаёт 192 кГц, обратно вниз широким ядром |

Аудио пишется AAC 256 kbps.

## Картинка

| Настройка | Зачем |
|---|---|
| `-sws_flags lanczos+accurate_rnd+full_chroma_int` | swscale работает и внутри `zoompan`, который пересчитывает каждый кадр панча — без этого он самое мыло в цепочке |
| `format=yuv444p` на всю цепочку, `yuv420p` один раз в `[vout]` | сабы и стикеры накладываются поверх; в половинной цветности у цветного текста расползаются края |
| `-crf 16 -preset medium` | TikTok всё равно пережмёт, мастер должен пережить второе поколение |
| `-colorspace/-color_primaries/-color_trc bt709` | иначе плеер угадывает и цвет уезжает |

## Сабы

Заголовок в начале ролика + подпись на каждый удар. Пул — 30 фраз на язык
(`CAPTIONS` в `src/crcut/plan.py`), упорядочен парами «интрига → расплата», чтобы
любой кусок читался как нагнетание:

```
СМОТРИ ДО КОНЦА → ЭТО БЫЛО БОЛЬНО → НЕ МОРГАЙ → ОН В ШОКЕ → СЕЙЧАС БУДЕТ → ЛАСТ ХИТ
```

Позиция в пуле сквозная на весь прогон, а не своя у каждого ролика, поэтому в трёх
вариантах одного прогона ни одна фраза не повторяется (тест
`test_no_caption_is_reused_across_variants`). Хочешь свои — правь список, он плоский.

## Озвучка

Каждый саб ещё и зачитывается вслух — голосом деда. Дед именно **делается**, а не
берётся: в macOS ровно один русский голос (женский `Milena`), поэтому синтез
пропускается через ffmpeg. Качество здесь съедает сам сдвиг тона (`asetrate` +
`atempo` мылят тем сильнее, чем дальше двигаешь), поэтому сдвиг держится на 3
полутонах, а возраст набирается вокруг него: тёплый бугор на 220 Гц, выеденная
«коробка» на 520 Гц, снятое шипение (`deesser`), медленное дрожание (`vibrato`) и
маленькая комната (`aecho`). Музыка под голосом сама приседает с 0.9 до 0.55.

Стилей пять — `STYLES` в `src/crcut/voice.py`, у каждого своя скорость чтения, свой
сдвиг и своя цепочка:

| `--voice-style` | F0 | Кто это |
|---|---|---|
| `grandpa` (по умолчанию) | 172 Гц | дед: −3 полутона, тело и комната, минимум артефактов |
| `grandpa_deep` | 171 Гц | дед постарше: −4 полутона, тяжелее, но заметнее мылит на длинных гласных |
| `hype` | 217 Гц | тиктокер-комментатор: быстро, ярко, прибито компрессором |
| `rasp` | 185 Гц | треш-стрим: хрип, гнусавость, орёт в дешёвый микрофон |
| `clean` | 219 Гц | голос как есть, только выровнен — без сдвига, без артефактов |

`rasp` — это **типаж, а не конкретный человек**. Клонировать чей-то голос crcut не
умеет и не будет: модели голоса тут нет вообще, есть системный `say` и цепочка
фильтров. Хрип собирается из `acrusher` (битовая грязь) + `aexciter` (верхние
гармоники), гнусавость — бустом +6 дБ на 1.4 кГц и провалом −4 дБ на 400 Гц, крик —
компрессором 8:1 и полосой 150–6000 Гц «как через телефон».

Одинаковый питч и темп на каждой строке — главное, что выдаёт синтез. Поэтому от
текста фразы считается хэш и им же двигается скорость (±12 слов/мин) и высота
(±2.4%). Сдвиг детерминированный, так что кэш `vo_*.wav` продолжает попадать, но
соседние реплики звучат по-разному.

```bash
uv run crcut --voices                          # ru_RU  Milena / en_GB  Grandpa (…) / …
uv run crcut inbox --lang en --voice Grandpa   # настоящий дед из комплекта macOS
uv run crcut inbox --voice-style grandpa_deep  # пониже и потяжелее
uv run crcut inbox --voice-style rasp          # хриплый треш-стрим
uv run crcut inbox --no-voice                  # без озвучки
```

Голосов в системе может быть сколько угодно: **Системные настройки → Универсальный
доступ → Устный контент → Системный голос → Управление голосами**. Всё, что там
установлено, сразу видно в `--voices` и работает в `--voice`. Имя можно писать
началом — macOS показывает голоса как `Grandpa (Англійська (США))`, а своих
`Grandpa` держит по одному на язык: берётся тот, что говорит на языке `--lang`.
Без флага берётся предпочтительный для языка (`PREFERRED` в `voice.py`).

### Реплики между сабами

Дед не только читает написанное — он ещё и комментирует. Пул `ADLIBS` в
`src/crcut/plan.py`, 16 фраз на язык («Ох ты ж!», «Ну ты даёшь!», «Э, куда
собрался?!», «Молодец, внучек!»), и эти фразы **нигде не пишутся на экране** —
только звук. Раз на экран они не идут, знаки препинания там свободны, и они
работают: `say` по «!» и «...» строит другую интонацию, поэтому реплики написаны
восклицаниями и многоточиями, а не точками.

Вешаются на хвост момента, **через каждый третий**, иначе дед не замолкает: саб
читается на самом ударе, реплика идёт через 0.25с после неё, так что две дорожки не
наезжают. Позиция в пуле, как и у сабов, сквозная на прогон — в трёх вариантах
реплики не повторяются (тест `test_adlibs_are_spoken_between_the_captions_and_never_repeat`).

**Читается не каждый саб.** У сегмента есть флаг `narrate`: заголовок вслух всегда
(он задаёт голос), дальше — через один. Остальные подписи просто рисуются. Так
дед комментирует ролик, а не диктует его; на реальном футаже это 10/7/13 озвученных
строк → 6/4/7.

Реплики кэшируются в `out/.cache/vo_*.wav` по хэшу «текст + голос + цепочка», так
что второй прогон их не пересинтезирует. Вне macOS (`say` нет) рендер просто идёт
без озвучки.

## Что накладывается сверху

| Слой | Где | Как сделано |
|---|---|---|
| Плавные переходы | только на реальной смене кадра, 0.3с | `xfade`: smoothleft / dissolve / circleopen / smoothup / smoothright / fadegrays |
| Панч-зум + тряска | на `hit` и `hook` | `zoompan`, зум 1.10→1.0 за 0.3с, тряска затухает за 0.2с |
| Сабы | заголовок в начале + подпись на каждый удар | PNG через Pillow (в ffmpeg нет `drawtext`), выезжают снизу |
| Шкала досмотра | верх кадра, 9px | `overlay` жёлтой полосы (в `drawbox` `t` — это толщина, не время) |
| Мемы-стикеры | `assets/memes/*.png` на каждый удар | тот же оверлей, ширина 42% кадра |
| SFX | только файлы из `assets/sfx/`, по одному на момент | `adelay` + `amix`; пустая папка = слоя нет |
| Озвучка | заголовок + каждый второй саб | `say` + состаривание в ffmpeg, музыка приседает под голос |
| Реплики деда | через каждый третий момент, только звук | те же `say` + цепочка, на 0.25с позже саба |

Внутри одного окна (`lead` → `hit` → `tail`) кадры идут подряд по времени
исходника — переход там читался бы как заикание, поэтому там жёсткий стык.

Эмодзи живут только в `.txt` рядом с видео: Pillow не рисует цветные эмодзи, в
кадр идёт текст без них.

## Пайплайн

```
inbox/*.mp4 → probe → сэмплинг кадров → motion / flash / shake + гейт матча
            → окна хайлайтов → скоринг → сегменты (lead 1.35x / hit 0.55x / tail)
            → cold open + хронология → переходы + сабы → снап к битам музыки
            → out/plan.json → один проход ffmpeg на вариант
            → out/montage_v{1,2,3}_*.mp4 + .txt
```

`out/plan.json` — точка вмешательства: правь тайминги руками и рендери
`--from-plan`, не переанализируя видео.

## Ассеты

| Папка | Что кладёшь | Без неё |
|---|---|---|
| `assets/music/` | треки, свой на вариант (сейчас 15 шт., CC-BY) | синтезированные беды 140 BPM |
| `assets/sfx/` | удары (`.wav/.mp3/.m4a/.aac/.ogg`), крутятся по кругу | звукового слоя нет |
| `assets/memes/` | стикеры `.png` с альфой | без стикеров |
| `assets/fonts/` | свой `.ttf/.otf` для сабов | Arial Black из системы |

## Разработка

```bash
uv run pytest -v                                  # синтетическая фикстура + e2e
uv run python tests/fixtures/make_fake_cr.py      # пересобрать фикстуру
```

Фикстура — синтетический «фейк-CR» ролик: 3с экрана загрузки, 24с матча, 3с
экрана победы. Внутри матча — три удара (вспышка + тряска) на известных
таймкодах; детект обязан найти все три и не вылезти за границы матча.

Пороги детекта — в `DetectConfig` (`src/crcut/detect.py`); это то, что
калибруется на реальном футаже.

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| `no video files in inbox` | в папке нет `.mp4/.mov/.m4v/.avi/.mkv` — проверь расширение |
| `no highlight windows found` | детект ничего не нашёл: `--analyze-only --debug` и смотри `out/debug/signals_*.csv`; пороги — в `DetectConfig` (`src/crcut/detect.py`) |
| `ffmpeg not found` | поставь ffmpeg, он должен быть в `PATH` вместе с `ffprobe` |
| Сабы без эмодзи | так и задумано: Pillow не рисует цветные эмодзи, они остаются в `.txt` |
| Ролик короче ожидаемого | материала не хватило — crcut не тянет паузами, только режет короче |
| Не те моменты в монтаже | правь тайминги прямо в `out/plan.json` и рендери `--from-plan out/plan.json` |
